# automation-runner-lib

A small, runtime-agnostic engine for scheduled automations. This file is the standing guidance for any
person or coding agent working in this repository.

## What it is (and is not)

- It runs one automation per invocation: runtime adapter → optional apply adapter → output adapters →
  run state. It does **not** schedule anything: cron, systemd timers or a CI schedule trigger it.
- Adapters are registered by name (`registerRuntime`, `registerApply`, `registerOutput`). The library
  ships only adapters that need no extra dependency (`console`, `slack-webhook`). Anything specific to a
  product (Jira, Bitbucket, an LLM CLI, a vault) belongs in the consuming repository, not here.
- Runtimes only read and render. The **apply adapter** is the only place allowed to write, and a write
  that means "this was announced" goes in `deferredCommit`, which the runner calls only after delivery.

## Rules for changes

- Do not add product-specific adapters, names, IDs, URLs or sample data from a real system. Examples use
  fictional data.
- Keep runtime dependencies minimal (today only `yaml`). A new dependency needs a reason in the PR.
- New behaviour needs a test in `src/**/*.test.ts` (`node:test`, run with `npm test`).
- Paths are injected through `RunnerConfig`; the library never assumes a project layout.
- Secrets are never committed. CI runs `gitleaks`; do not rely on it as the first line of defence.

## Commits and releases

Every commit is a Conventional Commit in English, with an allowed scope when it helps
(see [RELEASING.md](RELEASING.md) for the full rules). Versions and the changelog are generated by
release-please from those commits: never edit `version` in `package.json` or `CHANGELOG.md` by hand, and
never create a `v*` tag by hand. The default branch is `main`.

## Commands

```sh
npm ci
npm run typecheck && npm test && npm run build
npx tsx examples/new-items/main.ts new-items --no-delivery   # runnable example
```
